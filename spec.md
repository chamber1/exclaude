# Спецификация проекта test2

Состояние на 19.11.2026.

## 1. Назначение

Laravel-приложение:
- аутентификация пользователей;
- страница веб-камеры: пользователь видит изображение со своей камеры, делает снимки и хранит их в личной галерее;
- B2C-сервис загрузки звука и видео из роликов YouTube через очередь задач, для гостей и пользователей с тарифами.

Аудит и статус исправлений — `AUDIT.md`. Архитектура — `docs/ARCHITECTURE.md`. Запуск и деплой — `docs/DEPLOYMENT.md`.

## 3. Функциональность

### 3.1. Аутентификация (стандартная laravel/ui)
Регистрация, вход, выход, сброс пароля, подтверждение email (маршруты `Auth::routes()`). После входа пользователь попадает на `/home`.

### 3.2. Веб-камера

**Доступ:** только для вошедших пользователей. Гость перенаправляется на `/login`. В навбаре для вошедших пользователей есть ссылка «Веб-камера».

**Страница `/webcam`:**
1. Кнопка «Включить камеру» запрашивает доступ через `getUserMedia` и показывает поток в `<video>`.
2. Кнопка «Выключить» останавливает все треки потока. Поток также останавливается при уходе со страницы.
3. Переключатель «Маска клоуна 🤡» накладывает маску на каждое лицо в кадре (до 3 лиц) в реальном времени:
   - белый грим по контуру лица;
   - радужный парик;
   - синие треугольники над и под глазами;
   - высокие чёрные брови;
   - румяна на щеках;
   - увеличенный красный рот;
   - красный нос-шар.

   Маска поворачивается вместе с наклоном головы.
   - Распознавание лица: MediaPipe Face Landmarker (`@mediapipe/tasks-vision@0.10.14` с jsDelivr, модель `face_landmarker.task` из Google Storage).
   - Библиотека и модель загружаются только при первом включении переключателя, пока идёт загрузка, показывается статус. Сначала используется GPU, при ошибке — CPU.
   - Видео обрабатывается только в браузере, на сервер кадры не уходят.
   - Если модель не загрузилась, показывается ошибка, переключатель выключается.
4. Кнопка «Сделать снимок» сохраняет кадр так, как он виден на экране: с маской, если она включена. Кадр переводится в JPEG (качество 0.9) и отправляется на сервер. Новый снимок появляется в начале галереи без перезагрузки страницы.
5. Галерея «Мои снимки» показывает снимки текущего пользователя, новые сверху. Каждый снимок открывается в новой вкладке и удаляется после подтверждения.
6. Ошибки выводятся над видео:
   - небезопасный контекст (не https и не localhost);
   - доступ запрещён;
   - камера не найдена;
   - камера занята;
   - не загрузилась модель лица;
   - ошибка сохранения или удаления.

**Маршруты:**

| Метод | URL | Имя | Действие | Ответ |
|---|---|---|---|---|
| GET | `/webcam` | `webcam.index` | Страница с камерой и галереей | HTML |
| POST | `/webcam/snapshots` | `webcam.store` | Сохранить снимок (поле `image`) | `201` JSON `{id, url, created_at}`; `422` при ошибке валидации |
| GET | `/webcam/snapshots/{id}` | `webcam.show` | Отдать файл снимка владельцу | `200` image; `404` для чужого или отсутствующего снимка |
| DELETE | `/webcam/snapshots/{id}` | `webcam.destroy` | Удалить запись и файл | `204`; `404` для чужого снимка |

**Валидация загрузки:** обязательное поле, изображение jpeg или png, не больше 5 МБ.

**Хранение:**
- Таблица `webcam_snapshots`: `id`, `user_id` (FK → `users`, каскадное удаление), `path`, `timestamps`.
- Файлы лежат на приватном диске `local` в `storage/app/webcam/{user_id}/`. Публичной ссылки нет, файлы отдаются только через `webcam.show` с проверкой владельца.

**Файлы реализации:** `routes/web.php`, `app/Http/Controllers/WebcamController.php`, `app/Models/WebcamSnapshot.php`, `app/Models/User.php` (связь `webcamSnapshots`), `database/migrations/2026_11_18_000000_create_webcam_snapshots_table.php`, `resources/views/webcam.blade.php`, `resources/views/layouts/app.blade.php` (пункт меню).

### 3.3. Загрузки: звук и видео из ролика YouTube (`/parser`)

**Доступ:** открыт гостям (с меньшими лимитами) и вошедшим пользователям. Ссылка «Парсер» в навбаре видна всем. Архитектура — `docs/ARCHITECTURE.md`.

**Страница `/parser`** (разметка Bootstrap прежняя, без JS-фреймворков, вёрстка подстраивается под телефон):
1. Пользователь вставляет ссылку. Подходят `youtube.com/watch?v=`, `youtu.be/`, `/shorts/`, `/embed/`, `/live/` и поддомены `www.`, `m.`, `music.`.
2. Через 0,7 с после ввода корректной ссылки (или по кнопке «Проверить», или по Enter) идёт `POST /downloads/inspect`. Страница показывает:
   - превью, название, автора, длительность и максимальное качество;
   - значок «Creative Commons», если ролик под этой лицензией.

   Только после проверки открываются настройки.
3. Переключатель «🎵 Звук / 🎬 Видео». Настройки скрытого режима не отправляются.
   - **Звук:** формат MP3 или M4A, битрейт «Максимальное» / 320 / 256 / 192 / 128 / 96 / 64 кбит/с, подсказка с размером в МБ/мин.

     | | MP3 | M4A |
     |---|---|---|
     | «Максимальное» | VBR V0 (`--audio-quality 0`) | исходная AAC-дорожка без перекодирования |
     | Число | CBR, ровно выбранный битрейт | перекодирование в AAC; источник — Opus-дорожка (`bestaudio[acodec^=opus]`) |

   - **Видео (MP4):** «Максимальное», 2160p, 1440p, 1080p, 720p, 480p, 360p. Это **максимальная** высота кадра: если такого качества нет, берётся ближайшее ниже.
     - Качества выше, чем есть в ролике, помечены «нет в ролике».
     - Качества выше лимита тарифа помечены «после входа» или «на другом тарифе» и недоступны.
     - Выбор потоков: `-f "bv*+ba/b" -S "res:<высота>,vcodec:h264,acodec:aac" --merge-output-format mp4`. До 1080p получается H.264 + AAC, выше — VP9/AV1 (в подсказке есть предупреждение).
4. «Скачать звук/видео» отправляет `POST /downloads`: создаётся задача, ответ `202` приходит сразу. Дальше страница каждые 1,5 с опрашивает `status_url`:
   - статусы «в очереди» → «скачиваю на сервер» (прогресс 0–90 %) → «конвертирую» (95 %) → «готово»;
   - потом кнопка «⬇ Скачать файл» с именем, размером и сроком ссылки.
5. Ссылка на файл — временная подписанная (`?expires=…&signature=…`) и **одноразовая**: после скачивания задача становится `expired`, повторный запрос получает `410`. Неполученный файл удаляется через `DOWNLOADS_FILE_TTL` (1 ч).
6. Блок «Мои загрузки за сутки» показывает последние 10 задач владельца. После перезагрузки страницы активная задача продолжает отслеживаться.
7. Имя файла: `Название (720p).mp4`, `Название (192 kbps).mp3`. Для «Максимального» качества суффикса нет.
8. Ошибки показываются по-русски, без внутренних деталей: ссылка не YouTube или некорректная, внутренний адрес, ролик длиннее 60 минут, трансляция, нет лицензии CC (в режиме `creative_commons`), приватное, удалённое, с возрастным ограничением, только для спонсоров, платное, DRM, YouTube ограничивает запросы, таймаут, файл больше лимита тарифа, лимиты (активные задачи, в минуту, в сутки), сервис занят (503), устарела сессия (419).

**Лимиты:**

| | Гость | Free | Premium |
|---|---|---|---|
| Активных задач | 1 | 2 | 5 |
| В минуту | 3 | 10 | 30 |
| В сутки | 10 | 50 | 500 |
| Качество | до 720p | до 2160p | до 2160p |
| Размер файла | 500 МБ | 2 ГБ | 4 ГБ |

Все лимиты задаются в `config/downloads.php` и `.env`. Тариф хранится в `users.plan` (`free`/`premium`) и `users.plan_expires_at`.

**Маршруты:**

| Метод | URL | Имя | Параметры | Ответ |
|---|---|---|---|---|
| GET | `/parser` | `parser.index` | — | HTML |
| POST | `/downloads/inspect` | `downloads.inspect` | `url` | `200` JSON: `id`, `title`, `duration`, `uploader`, `thumbnail`, `license`, `creative_commons`, `max_available_height`, `qualities[{value, available, allowed}]`, `limits{plan, guest, max_height}`; `422`/`429`/`503` `{message, code, errors.url}` |
| POST | `/downloads` | `downloads.store` | `url`, `type` (`audio`/`video`), `format` + `bitrate` (звук) или `quality` (видео) | `202` задача; `422` (валидация, `errors.<поле>`), `429`, `503` |
| GET | `/downloads` | `downloads.index` | — | задачи владельца за сутки (до 10) |
| GET | `/downloads/{uuid}` | `downloads.show` | — | задача: `id`, `status`, `progress`, `type`, `format`, `bitrate`, `quality`, `title`, `duration`, `error`, `error_code`, `file{name, size, url}`, `downloaded`, `expires_at`, `status_url`…; `404` для чужой |
| GET | `/downloads/{uuid}/file` | `downloads.file` | подписанная ссылка | файл (через `X-Accel-Redirect`); `403` без подписи или с истёкшей; `404` для чужой задачи; `410` после скачивания |
| GET | `/up` | — | — | `200`/`503` JSON проверки здоровья |

Старые `POST /parser` и `GET /parser/files/{token}` удалены (синхронное скачивание в запросе).

**Хранение:**
- Таблица `download_tasks`:
  - идентификаторы: `uuid` (публичный);
  - владелец: `user_id` или `guest_id` (HMAC токена сессии), `client_hash` (HMAC IP);
  - что скачивается: `platform`, `media_id`, `type`, `format`, `bitrate`, `quality`;
  - состояние: `status`, `progress`, `attempts`, `error_code`, `error_message`;
  - результат: `title`, `duration`, `file_*`;
  - время: `started/completed/expires/downloaded_at`.
- Файлы лежат в `storage/app/downloads/<uuid>/media.<ext>`.
- Сырой IP нигде не хранится.

**Обработка:** `DownloadJob` в очереди `downloads` (Redis), контейнер `queue-worker`. Безопасность команды yt-dlp:
- массив аргументов;
- канонический URL из ID после `--`;
- `--ignore-config`, `--use-extractors youtube`, `--no-playlist`;
- `--match-filter "duration <= 3600 & !is_live"`, `--max-filesize` тарифа;
- таймаут 600 с.

Повтор после падения воркера, очистка, мониторинг — `docs/ARCHITECTURE.md`.

**Журнал:** `storage/logs/downloads-YYYY-MM-DD.log` (канал `downloads`, 14 дней):
- создание, обработка, завершение, ошибки и выдача задач;
- при сбое — вывод yt-dlp.

**Файлы реализации:**
- `app/Downloads/*`, `app/Jobs/DownloadJob.php`, `app/Models/DownloadTask.php`;
- `app/Http/Controllers/{DownloadController,ParserController,HealthController}.php`, `app/Http/Requests/*DownloadRequest.php`, `app/Http/Resources/DownloadTaskResource.php`;
- `app/Console/Commands/Downloads*.php`, `app/Console/Kernel.php`, `app/Providers/{App,Route}ServiceProvider.php`;
- `config/downloads.php`, `resources/views/parser.blade.php`, `routes/web.php`;
- миграции `2026_11_19_*`.

## 4. Проверено

- Миграции применены (батч 1 — стандартные, батч 2 — `webcam_snapshots`).
- HTTP-сценарий от гостя и от вошедшего пользователя:
  - гость перенаправляется на вход;
  - сохранение снимка → `201`;
  - просмотр владельцем → `200 image/jpeg`;
  - загрузка не-изображения → `422`;
  - удаление → `204`, файл удаляется с диска.
- PHP внутри контейнера выполняет HTTPS-запросы (CA bundle `/etc/ssl/certs/ca-certificates.crt`).

- Маска клоуна: JS страницы проходит проверку синтаксиса. Функция рисования маски отработала на тестовых точках лица без ошибок. CDN-файлы MediaPipe и модель доступны (200).

- Автотесты (19.11.2026): `vendor/bin/phpunit` — **167 тестов, 496 проверок, все проходят**.
  - Unit: `UrlParser`, `NetworkGuard`, `ProgressTracker`, `YtDlpErrors`.
  - Feature: inspect, валидация, SSRF без запуска yt-dlp, создание и очередь, лимиты гостя и тарифов, статусы, владелец, подписанные ссылки и их срок, X-Accel, задача в воркере (успех, ошибки, таймаут, повтор после падения, `failed()`), очистка, расписание, доступ к `/webcam` и `/parser`, `/up`.
  - yt-dlp подменяется через `Process::fake()`, реальных обращений к YouTube нет.
- Сквозная проверка на работающем стеке (19.11.2026, реальный YouTube):
  - SSRF-ссылки (`127.0.0.1`, `169.254.169.254`, `mysql:3306`, `2130706433`, `file://`, look-alike, userinfo, порт 8080, сокращатель) → `422`;
  - ролик 61 мин → `too_long`; без чекбокса прав → `422`; гость 1080p → `quality_not_allowed`; вторая активная задача → `429`;
  - создание `202` → `pending` → `processing 0…42` → `completed 100`;
  - чужой посетитель: статус `404`, файл `404`; подделанная подпись `403`;
  - файл отдаёт nginx: `200`, `ffprobe` подтверждает H.264+AAC и MP3 128 кбит/с; повторно `410`;
  - production-образы собираются; production-конфиг nginx проходит `nginx -t`; `docker-compose.prod.yml` валиден.

- Синхронный парсер (до перевода на очередь, 18.11.2026):
  - гость перенаправляется на вход, страница открывается (200);
  - ссылки не YouTube, некорректный ID, попытка передать опцию (`--exec=...`) и неверный формат отклоняются с `422`;
  - без `yt-dlp` возвращается понятная ошибка;
  - разбор ссылок в JS: правильно извлекает ID и отвергает `evil.com` и `youtube.com.evil.com`;
  - конфиг nginx валиден.
  - Реальное скачивание (образ пересобран: yt-dlp 2026.10.26, deno 2.9.8, ffmpeg 4.4.2) на ролике `jNQXAC9IVRw` (19 с). Все 7 комбинаций вернули `200` за 5–10 с, битрейт подтверждён `ffprobe`:

    | Формат | Битрейт | Результат |
    |---|---|---|
    | MP3 | best | 139 кбит/с |
    | MP3 | 320 / 128 / 64 | ровно 320 / 128 / 64 |
    | M4A | best | 128 кбит/с |
    | M4A | 192 / 96 | 195 / 97 |

    Битрейт `999` → `422`. Временных файлов после запросов не осталось.
  - Видео (проверено на `jNQXAC9IVRw` и `aqz-KE-bpKQ` Big Buck Bunny, CC-BY), кодеки подтверждены `ffprobe`:

    | Ролик | Качество | Время | Результат |
    |---|---|---|---|
    | Me at the zoo | Максимальное | 7 с | 240p H.264 + AAC, 0,6 МБ |
    | Big Buck Bunny | 480p | 14 с | 480p H.264 + AAC, 57 МБ (отдельные потоки склеены в MP4) |
    | Big Buck Bunny | 360p | 8 с | 360p H.264 + AAC, 27 МБ |

    - В режиме симуляции для Big Buck Bunny выбор форматов такой: 2160p → VP9 + AAC (~1,4 ГБ); 1080p и 720p → H.264 + AAC.
    - Одноразовая ссылка: владелец получает `200 video/mp4`, повторный запрос — `404`; гость перенаправляется на вход; другой пользователь получает `404`, файл владельца при этом остаётся.
    - Несуществующий или некорректный токен → `404`.
    - `quality=999`, видео без `quality`, `type=exe` → `422`.
    - Скачивание звука после изменений по-прежнему работает (MP3 128 кбит/с).
  - Журнал `parser.log`: для каждого сценария записываются нужные строки — успешные звук и видео, недоступный ролик, ролик длиннее 60 минут (`0-s_qZRWElA`, 1:00:14), не-YouTube ссылка, неверный битрейт, повторный и некорректный токен. Файл журнала принадлежит `www-data`.

**Не проверено:**
- Ролики длиной 30–60 минут: время обработки близко к таймаутам. Особенно это касается видео в 1080p и выше.
- Видео в 1440p/2160p целиком скачано не было, проверен только выбор формата в симуляции.
- Работа камеры и маски в реальном браузере: точность положения маски на настоящем лице и скорость кадров.
- Изоляция снимков между двумя разными пользователями. Код её обеспечивает, но отдельно она не тестировалась.

## 5. Известные проблемы и бэклог

- [x] ~~Нет автотестов; `phpunit.xml` указывал на рабочую БД~~ — отдельная база `laravel_test`, 166 тестов.
- [x] ~~`chmod -R 777`~~, ~~Composer не устанавливался в образе~~, ~~парсер синхронный~~ — исправлено (см. `AUDIT.md`, раздел 5).
- [x] ~~PHP 8.1 и Laravel 10 без поддержки безопасности~~ — PHP 8.5, Laravel 13 (`docs/UPGRADE.md`).
- [ ] Лишняя миграция `password_resets`: Laravel 10+ использует `password_reset_tokens`.
- [ ] Структура приложения осталась от Laravel 10 (Kernel-классы, полные конфиги). Работает в Laravel 13; переход на `bootstrap/app.php` — по желанию (`docs/UPGRADE.md`).
- [ ] Автотесты веб-камеры покрывают только доступ (вход обязателен), сохранение и удаление снимков не тестируются.
- [ ] Если открыть https://localhost при запущенном `npm run dev`, браузер заблокирует ресурсы Vite: dev-сервер работает по HTTP. Используйте http://localhost или `npm run build`.
- [ ] Маске клоуна нужен интернет (jsDelivr и Google Storage). Для работы офлайн библиотеку и модель можно положить в `public/`.
