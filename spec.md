# Спецификация проекта test2

Состояние на 18.11.2026.

## 1. Назначение

Учебное Laravel-приложение: аутентификация пользователей и страница веб-камеры. На этой странице пользователь видит изображение со своей камеры, делает снимки и хранит их в личной галерее.

## 2. Стек и окружение

| Слой | Технология |
|---|---|
| Backend | Laravel 10, PHP 8.1, Sanctum, laravel/ui |
| Frontend | Blade, Bootstrap 5, Sass, Vite, vanilla JS |
| БД | MySQL 8.0 |
| Инфраструктура | Docker Compose: `nginx` (80/443), `php_fpm`, `mysql` (3306) |

- Адреса: http://localhost и https://localhost. Для HTTPS используется самоподписанный сертификат, поэтому браузер покажет предупреждение.
- Тестовый пользователь: `test@test.com` / `password`.

## 3. Функциональность

### 3.1. Аутентификация (стандартная laravel/ui)
Регистрация, вход, выход, сброс пароля, подтверждение email (маршруты `Auth::routes()`). После входа пользователь попадает на `/home`.

### 3.2. Веб-камера

**Доступ:** только для вошедших пользователей. Гость перенаправляется на `/login`. В навбаре для вошедших пользователей есть ссылка «Веб-камера».

**Страница `/webcam`:**
1. Кнопка «Включить камеру» запрашивает доступ через `getUserMedia` и показывает поток в `<video>`.
2. Кнопка «Выключить» останавливает все треки потока. Поток также останавливается при уходе со страницы.
3. Переключатель «Маска клоуна 🤡» накладывает маску на каждое лицо в кадре (до 3 лиц) в реальном времени:
   - белый грим по контуру лица;
   - радужный парик;
   - синие треугольники над и под глазами;
   - высокие чёрные брови;
   - румяна на щеках;
   - увеличенный красный рот;
   - красный нос-шар.

   Маска поворачивается вместе с наклоном головы.
   - Распознавание лица: MediaPipe Face Landmarker (`@mediapipe/tasks-vision@0.10.14` с jsDelivr, модель `face_landmarker.task` из Google Storage).
   - Библиотека и модель загружаются только при первом включении переключателя, пока идёт загрузка, показывается статус. Сначала используется GPU, при ошибке — CPU.
   - Видео обрабатывается только в браузере, на сервер кадры не уходят.
   - Если модель не загрузилась, показывается ошибка, переключатель выключается.
4. Кнопка «Сделать снимок» сохраняет кадр так, как он виден на экране: с маской, если она включена. Кадр переводится в JPEG (качество 0.9) и отправляется на сервер. Новый снимок появляется в начале галереи без перезагрузки страницы.
5. Галерея «Мои снимки» показывает снимки текущего пользователя, новые сверху. Каждый снимок открывается в новой вкладке и удаляется после подтверждения.
6. Ошибки выводятся над видео:
   - небезопасный контекст (не https и не localhost);
   - доступ запрещён;
   - камера не найдена;
   - камера занята;
   - не загрузилась модель лица;
   - ошибка сохранения или удаления.

**Маршруты:**

| Метод | URL | Имя | Действие | Ответ |
|---|---|---|---|---|
| GET | `/webcam` | `webcam.index` | Страница с камерой и галереей | HTML |
| POST | `/webcam/snapshots` | `webcam.store` | Сохранить снимок (поле `image`) | `201` JSON `{id, url, created_at}`; `422` при ошибке валидации |
| GET | `/webcam/snapshots/{id}` | `webcam.show` | Отдать файл снимка владельцу | `200` image; `404` для чужого или отсутствующего снимка |
| DELETE | `/webcam/snapshots/{id}` | `webcam.destroy` | Удалить запись и файл | `204`; `404` для чужого снимка |

**Валидация загрузки:** обязательное поле, изображение jpeg или png, не больше 5 МБ.

**Хранение:**
- Таблица `webcam_snapshots`: `id`, `user_id` (FK → `users`, каскадное удаление), `path`, `timestamps`.
- Файлы лежат на приватном диске `local` в `storage/app/webcam/{user_id}/`. Публичной ссылки нет, файлы отдаются только через `webcam.show` с проверкой владельца.

**Файлы реализации:** `routes/web.php`, `app/Http/Controllers/WebcamController.php`, `app/Models/WebcamSnapshot.php`, `app/Models/User.php` (связь `webcamSnapshots`), `database/migrations/2026_11_18_000000_create_webcam_snapshots_table.php`, `resources/views/webcam.blade.php`, `resources/views/layouts/app.blade.php` (пункт меню).

### 3.3. Парсер: звук из ролика YouTube

**Доступ:** только для вошедших пользователей. В навбаре есть ссылка «Парсер».

**Страница `/parser`:**
1. Пользователь вставляет ссылку. Подходят `youtube.com/watch?v=`, `youtu.be/`, `/shorts/`, `/embed/`, `/live/` и поддомены `www.`, `m.`, `music.`. Для корректной ссылки сразу показывается превью ролика (`i.ytimg.com`).
2. Выбор формата: MP3 или M4A (AAC).
3. Выпадающий список «Битрейт»: «Максимальное», 320, 256, 192, 128, 96, 64 кбит/с. Под списком подсказка с примерным размером файла в МБ на минуту. Если выбрано больше 160 кбит/с, добавляется предупреждение: звук на YouTube обычно ~130–160 кбит/с, качество не вырастет.

   | | MP3 | M4A |
   |---|---|---|
   | «Максимальное» | VBR V0 (`--audio-quality 0`), битрейт зависит от исходника (на тесте 139 кбит/с) | Исходная AAC-дорожка без перекодирования (~128 кбит/с) |
   | Число | CBR, ровно выбранный битрейт (`--audio-quality 192K` → `-b:a 192k`) | Перекодирование в AAC с выбранным битрейтом. Источником берётся Opus-дорожка (`bestaudio[acodec^=opus]`): из AAC-источника yt-dlp просто копирует дорожку и битрейт игнорирует |

   Если битрейт не «Максимальное», он добавляется к имени файла: `Название (192 kbps).mp3`.
4. По кнопке «Скачать звук» запрос уходит через `fetch`, на кнопке крутится спиннер. Когда ответ готов, браузер сохраняет файл с названием ролика. После этого показываются размер файла и время обработки.
5. Ошибки выводятся под полем ссылки (ошибка битрейта — под списком):
   - ссылка не YouTube;
   - ролик длиннее 60 минут;
   - видео приватное, удалено, с возрастным ограничением или только для спонсоров;
   - трансляция ещё не началась;
   - YouTube блокирует запросы как от бота;
   - обработка не уложилась в 10 минут;
   - на сервере нет yt-dlp или ffmpeg;
   - слишком много запросов (429);
   - устарела сессия (419).

**Маршруты:**

| Метод | URL | Имя | Действие | Ответ |
|---|---|---|---|---|
| GET | `/parser` | `parser.index` | Форма | HTML |
| POST | `/parser` | `parser.download` | Поля `url`, `format` (`mp3`/`m4a`), `bitrate` (`best`/`320`/`256`/`192`/`128`/`96`/`64`) | `200` файл (attachment); `422` JSON с ошибкой в `errors.url`, `errors.format` или `errors.bitrate`; `429` при превышении лимита |

**Как работает:**
- `ParserController::download` вызывается синхронно, никаких очередей.
- Контроллер извлекает из ссылки 11-символьный ID ролика. В `yt-dlp` уходит только нормализованная ссылка `https://www.youtube.com/watch?v=<ID>` после `--`, исходный ввод пользователя туда не попадает.
- Параметры `yt-dlp`: `--no-playlist`, `--match-filter "duration <= 3600"`, `-x --audio-format <format> --audio-quality 0`.
- Файл сохраняется как `storage/app/parser/<uuid>.<ext>` и удаляется после отправки (`deleteFileAfterSend`). Файлы старше часа, оставшиеся от прерванных загрузок, удаляются при следующем запросе.
- Лимиты:
  - видео не длиннее 60 минут;
  - работа `yt-dlp` до 600 с;
  - `fastcgi_read_timeout 660s` в nginx;
  - не больше 10 запросов в минуту на пользователя (`throttle:10,1`).
- Путь к бинарнику задаётся в `config/services.php` → `yt_dlp.binary` (env `YTDLP_BINARY`, по умолчанию `/usr/local/bin/yt-dlp`). php-fpm очищает переменные окружения, поэтому `PATH`, `HOME` и `DENO_DIR` передаются процессу явно.
- Зависимости в образе `php_fpm` (`docker/Dockerfile`):
  - `ffmpeg` (apt);
  - `yt-dlp` (standalone-бинарник, последняя версия, без фиксации);
  - `deno` (JS-рантайм, нужен `yt-dlp` для YouTube).

**Файлы реализации:** `app/Http/Controllers/ParserController.php`, `resources/views/parser.blade.php`, `routes/web.php`, `config/services.php`, `docker/Dockerfile`, `docker/nginx/default.conf`, `resources/views/layouts/app.blade.php` (пункт меню).

## 4. Проверено

- Миграции применены (батч 1 — стандартные, батч 2 — `webcam_snapshots`).
- HTTP-сценарий от гостя и от вошедшего пользователя:
  - гость перенаправляется на вход;
  - сохранение снимка → `201`;
  - просмотр владельцем → `200 image/jpeg`;
  - загрузка не-изображения → `422`;
  - удаление → `204`, файл удаляется с диска.
- PHP внутри контейнера выполняет HTTPS-запросы (CA bundle `/etc/ssl/certs/ca-certificates.crt`).

- Маска клоуна: JS страницы проходит проверку синтаксиса. Функция рисования маски отработала на тестовых точках лица без ошибок. CDN-файлы MediaPipe и модель доступны (200).

- Парсер:
  - гость перенаправляется на вход, страница открывается (200);
  - ссылки не YouTube, некорректный ID, попытка передать опцию (`--exec=...`) и неверный формат отклоняются с `422`;
  - без `yt-dlp` возвращается понятная ошибка;
  - разбор ссылок в JS: правильно извлекает ID и отвергает `evil.com` и `youtube.com.evil.com`;
  - конфиг nginx валиден.
  - Реальное скачивание (образ пересобран: yt-dlp 2026.10.26, deno 2.9.8, ffmpeg 4.4.2) на ролике `jNQXAC9IVRw` (19 с). Все 7 комбинаций вернули `200` за 5–10 с, битрейт подтверждён `ffprobe`:

    | Формат | Битрейт | Результат |
    |---|---|---|
    | MP3 | best | 139 кбит/с |
    | MP3 | 320 / 128 / 64 | ровно 320 / 128 / 64 |
    | M4A | best | 128 кбит/с |
    | M4A | 192 / 96 | 195 / 97 |

    Битрейт `999` → `422`. Временных файлов после запросов не осталось.

**Не проверено:**
- Ролики длиной 30–60 минут: время обработки близко к таймаутам.
- Работа камеры и маски в реальном браузере: точность положения маски на настоящем лице и скорость кадров.
- Изоляция снимков между двумя разными пользователями. Код её обеспечивает, но отдельно она не тестировалась.

## 5. Известные проблемы и бэклог

- [ ] Нет автотестов для веб-камеры. Сначала нужно перевести `phpunit.xml` на SQLite in-memory, иначе тесты с `RefreshDatabase` сотрут рабочую БД.
- [ ] Лишняя миграция `password_resets`: Laravel 10 использует `password_reset_tokens`.
- [ ] В `docker/Dockerfile` установлены права `chmod -R 777` на `storage` и `bootstrap`. Для продакшена это небезопасно.
- [ ] В `docker/Dockerfile` закомментирована установка Composer, поэтому `vendor/` должен лежать на хосте.
- [ ] Если открыть https://localhost при запущенном `npm run dev`, браузер заблокирует ресурсы Vite: dev-сервер работает по HTTP. Используйте http://localhost или `npm run build`.
- [ ] Маске клоуна нужен интернет (jsDelivr и Google Storage). Для работы офлайн библиотеку и модель можно положить в `public/`.
- [ ] Парсер работает синхронно: пока идёт скачивание, занят один воркер php-fpm. Если пользователей станет много, лучше перейти на очередь (job + воркер) с опросом статуса.
- [ ] YouTube может блокировать запросы с сервера («not a bot»). Тогда помогают свежий `yt-dlp` (`docker exec php_fpm yt-dlp -U` или пересборка) либо cookies аккаунта.
- [ ] Скачивание с YouTube нарушает его условия использования. Использовать только для собственного контента или контента со свободной лицензией.
- [ ] Проект не под git.
